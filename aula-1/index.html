Tema 1 de 3

Como o Linux se organiza

Quando você digita ls, quem realmente lê o disco?

O Linux funciona em camadas, e cada uma só conversa com a vizinha. Você fala com o , que chama um programa (como o ls), que pede ao , e só o kernel mexe no hardware. É por isso que um programa comum não consegue apagar o arquivo de outro usuário: o kernel confere as permissões antes.

Os arquivos também têm uma organização própria. Não existe C:\: tudo fica numa única árvore que começa na /. Pendrives e discos aparecem como pastas dentro dela. Até dispositivos viram arquivos (é o famoso "tudo é arquivo").

/raiz de tudo
home/pastas dos usuários
aluno/sua , apelidada de ~
etc/configurações do sistema
usr/bin/os programas (o ls mora aqui)
var/log/registros (logs) do que acontece
dev/dispositivos, vistos como arquivos

Para chegar a um arquivo, você usa um caminho. O absoluto começa na raiz e funciona de qualquer lugar (/home/aluno/Documentos). O relativo parte de onde você está (Documentos). Dois atalhos aparecem o tempo todo: . é "aqui" e .. é "uma pasta acima".

Antes de rodar, pense: se você está em /home/aluno e digita cd .., onde vai parar? E depois de cd ~?
Pare e pense: você está em /home/aluno/Documentos. Para onde leva o caminho ../../etc?

Para /home/etc, que provavelmente nem existe. Cada .. sobe um nível: de Documentos para aluno, depois para home, e só então entra em etc. Para chegar na pasta de configurações do sistema, seria preciso subir mais um nível (../../../etc) ou, bem mais simples, usar o caminho absoluto /etc.

Leve para a aula: o kernel é o único que toca no hardware, e todos os arquivos vivem numa árvore só, a partir do /.

O que o shell faz quando você aperta Enter

Por que cat meu arquivo.txt diz que o arquivo não existe, se ele está bem ali?

A primeira coisa que o shell faz é quebrar a linha em palavras, usando os espaços. A primeira palavra é o comando; as outras são . As que começam com - são , que mudam o comportamento (ls -l). Um nome com espaço vira duas palavras, a não ser que você use aspas. Teste abaixo:

Depois, o shell precisa encontrar o programa. Ele não procura no computador inteiro: olha só nas pastas listadas no , em ordem. A pasta onde você está não faz parte dessa lista, por segurança. Por isso, para rodar um script seu, você escreve ./ola.sh: o ./ diz "este arquivo, aqui nesta pasta".

Antes de rodar, pense: o que acontece com ola.sh sem o ./? E com LS, em maiúsculas?
Pare e pense: quantos argumentos o cp recebe em cp "foto 1.jpg" fotos/?

Dois: foto 1.jpg (as aspas juntam as duas partes num argumento só) e fotos/. Sem as aspas, seriam três (foto, 1.jpg e fotos/), e o cp tentaria copiar dois arquivos que não existem.

Leve para a aula: espaço separa argumentos (use aspas em nomes com espaço), o shell só acha programas no PATH (seu script precisa de ./) e maiúsculas importam.

Tema 3 de 3

Para onde vai a saída

Como juntar comandos pequenos para fazer algo grande, sem escrever nenhum programa?

Todo programa nasce com três "canos" abertos: a entrada (), de onde ele lê; a saída (), onde escreve os resultados; e o canal de erros (). Normalmente a entrada é o teclado e as duas saídas vão para a tela. Mas a tela é só o destino padrão, e dá para mudá-lo.

Repare que saída e erro são canais separados. É isso que permite guardar os resultados num arquivo e ainda ver os erros na tela. E o | (pipe) é a ideia mais poderosa do Linux: ferramentas pequenas, cada uma fazendo uma coisa bem, ligadas em sequência.

Por fim, todo comando termina devolvendo um número, o : 0 significa sucesso e qualquer outro valor significa erro. Você não vê esse número, mas ele fica guardado em $?. Os scripts usam esse código para decidir o que fazer em seguida.

Antes de rodar, pense: em ls /etc /nao_existe 2> erros.txt, o que aparece na tela, e o que vai para o arquivo?
Pare e pense: num script de backup, como saber se a cópia deu certo antes de apagar o original?

Pelo código de saída. Se o cp falhar, ele devolve um número diferente de 0. Dá para encadear: cp dados.txt backup/ && rm dados.txt. O && só executa o rm se o cp tiver dado certo. Na aula, você vai ver como fazer o mesmo com if.

Leve para a aula: saída e erros são canais separados, que você redireciona com > e 2> ou liga a outro programa com |. E todo comando devolve um código: 0 é sucesso.

Para quem quiser ir além (opcional): quem pode o quê, as permissões

Cada arquivo tem um dono, um grupo e o resto do mundo (outros). Para cada um, três permissões: r (ler), w (escrever) e x (executar). O ls -l mostra isso como -rwxr-xr--, e o comando chmod muda as permissões. Cada permissão vale um número (r=4, w=2, x=1), e a soma de cada grupo forma o famoso chmod 755. Toque nos bits:
